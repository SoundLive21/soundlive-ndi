Préparer un nouveau lecteur SoundLive-NDI

Page de configuration : /addsshkey (HTTPS sur le port 8766).

Cette page transmet uniquement la clé SSH publique de ta régie. Elle ne donne pas accès à sa clé privée. Exécute la préparation sur le nouveau lecteur, puis clique sur Déployer dans la fiche de l'écran créé dans la régie.

Il faut être connecté à la régie en HTTPS pour consulter cette page. N'exécute pas ces commandes sur un ordinateur que tu ne souhaites pas administrer.

Clé publique de la régie

__SSH_PUBLIC_KEY__

Ubuntu Desktop et Raspberry Pi OS

Dans le terminal du nouveau lecteur, avec le compte qui affichera les vidéos :

__LINUX_COMMAND__

Cette commande installe OpenSSH et Git, autorise la régie dans ~/.ssh/authorized_keys, démarre le serveur SSH et affiche l'empreinte de la clé hôte du lecteur. Note le nom d'utilisateur, l'IPv4 et l'empreinte.

Dans le formulaire « Déployer », tu pourras renseigner le mot de passe sudo du compte Linux pour cette installation uniquement. Il n’est pas stocké par SoundLive-NDI. Tu peux aussi laisser ce champ vide si le compte dispose déjà de droits sudo sans saisie interactive. N'accorde pas des droits NOPASSWD:ALL à un compte personnel.

Windows 10 ou 11

Ouvre PowerShell en administrateur sur le nouveau lecteur, puis exécute :

__WINDOWS_COMMAND__

Cette commande installe le serveur OpenSSH, ajoute la clé au fichier administrators_authorized_keys, applique les permissions nécessaires et ouvre le pare-feu Windows sur TCP 22. Le compte choisi doit être administrateur pour l'installation distante. Git for Windows, Python et le runtime NDI peuvent être nécessaires pour la suite.

Finaliser depuis la régie

  1. Dans la régie, clique sur Ajouter un écran puis crée le lecteur Raspberry Pi, Ubuntu ou Windows. L'écran apparaît en attente avec un code valable 15 minutes.
  2. Sur le nouveau lecteur, exécute la préparation SSH ci-dessus et relève son adresse IPv4 et l'empreinte SHA256:… de la clé SSH hôte.
  3. Depuis la fiche En attente du tableau, clique sur Déployer via SSH.
  4. Indique l'IPv4 du lecteur, son utilisateur SSH, l'empreinte vérifiée et l'IPv4 du réseau écrans de la régie.
  5. La régie vérifie l'empreinte SSH, clone le dépôt GitHub officiel sur le lecteur et exécute l'installateur. L'association utilise le code du tableau.

Le nouveau lecteur doit pouvoir accéder à GitHub pour cloner le dépôt. Un Raspberry Pi neuf peut devoir télécharger et compiler le SDK NDI. Sous Windows, l'installation exige les prérequis du moteur NDI et un compte SSH administrateur. Cette préparation donne à la régie un accès SSH à ce compte : n'utilise cette méthode que pour des lecteurs que tu administres.
